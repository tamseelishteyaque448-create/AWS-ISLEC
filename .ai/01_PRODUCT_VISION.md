# Product vision

**Why:** AWS ISLEC exists to turn student interest and participation into visible, credible builder experience in a community context.

**What:** students should be able to become members, learn through challenges, discover and join projects, collaborate, attend events, accumulate evidence of meaningful work, progress through stages, and eventually lead.

**How:** the intended chain is `Student → Membership → Learning → Project discovery → Team formation → Building → Evidence → Progression → Leadership`. The product records authoritative domain events (challenge completion, attendance, approved project work and memberships) rather than treating UI state as evidence.

The repository implements public discovery, member participation, administration, projects, learning, events, activities, points, badges, and stages. It does not establish that every intended journey is browser-verified. Intentional non-goals currently include inventing uncontracted collaboration features, awarding V2.2 task/milestone points, or treating activity feeds as an authorization mechanism.

What must not be assumed: a visible feature is not proof of an authorized mutation path, and a product aspiration is not an implemented capability. NOT VERIFIED — requires runtime/database verification for live product behavior and production data.
