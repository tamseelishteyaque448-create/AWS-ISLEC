# Projects V1 and V2.1

Lifecycle: `Member → Create → Draft → Recruit → Submit for Review → Approved / Changes Requested → Published → Build → Shipped → Archived`. `publication_state` is authoritative (`draft`, `pending_review`, `published`, `changes_requested`, `archived`); `build_stage` is separate (`idea`, `building`, `prototype`, `shipped`). Legacy `status`/`is_published` are synchronized compatibility fields, not authority.

An active owner is required exactly once per project. Contributors have `project_members` rows; recruitment modes are `open`, `invite_only`, `not_recruiting`; capacity is optional but must be positive and cannot be exceeded by the join-resolution RPC. Owners create/update, submit for review, resolve join requests, and may transfer ownership to an active member. Admin recovery exists for an ownerless/legacy recovery case. Admin review writes a review decision and controls publication. Requests are `requested`, `withdrawn`, `declined`, or `approved`; approved requests create/reactivate contributor membership. V2.1 adds URL-only skill proofs to open join requests.

Protected RPCs include `create_project_v1`, `update_project_v1`, `admin_update_project_v1`, `request_project_join`, `withdraw_project_join_request`, `resolve_project_join_request`, `submit_project_for_review`, `review_project_publication`, `transfer_project_ownership`, `recover_project_ownership`, `submit_project_work`, `review_project_member`, and proof RPCs. Project and activity/point operations are transactional and database-authoritative. Project points: first review submission +50 owner; first approval/publication +150 owner; first approved join +30 contributor.

Deliberately excluded from V1/V2.1: V2.2 milestones/tasks, comments, subtasks, dependencies, task priorities/due dates, notifications, realtime, and GitHub integration.
